# Weather Signal Scoring Method

天气信号评分方法说明文档。

## 概述

本评分系统用于评估 Polymarket 天气市场数据源的可靠性，输出 0-10 分的综合评分，帮助交易者判断市场是否有足够的数据支撑进行结算验证。

## 评分组件

### 1. recency - 数据时效性 (权重: 30%)

**衡量指标**: 天气数据最新更新时间距离当前的时间间隔

**计算方法**:
- 提取 `weather-aviation-sources` 中各站点的 `observationTime`
- 计算与当前时间的差值（小时）
- 评分公式:
  - ≤1 小时: 10 分（满分）
  - 1-24 小时: 线性插值
  - >24 小时: 0 分

**数据来源**: `observationTime` 字段

---

### 2. model_agreement - 多站点一致性 (权重: 30%)

**衡量指标**: 多个气象站点之间观测/预测数据的一致程度

**计算方法**:
- 提取所有站点的温度数据
- 计算温度标准差 (stdDev)
- 评分公式:
  - stdDev ≤ 2°F: 10 分（高度一致）
  - stdDev ≥ 15°F: 0 分（严重分歧）
  - 中间值线性插值

**Proxy 说明**:
- 理想情况应使用多模型（如 GFS、ECMWF、HRRR）预报对比
- 当前使用 NOAA/NWS 多站点观测作为 proxy

---

### 3. volatility - 预测波动性 (权重: 20%)

**衡量指标**: 预报数据的多样性/变化程度

**计算方法**:
- 提取各站点未来 6-12 小时预报 (`forecast.shortForecast`)
- 统计预报类型的唯一值比例
- 评分公式:
  - 多样性 ≤ 20%: 10 分（预测稳定）
  - 多样性 ≥ 80%: 0 分（预测分歧大）
  - 中间值线性插值

**Proxy 说明**:
- 理想情况应使用历史预报变化序列
- 当前使用站点间预报多样性作为 proxy

---

### 4. data_gap_risk - 数据质量/缺失风险 (权重: 20%)

**衡量指标**: 数据完整性和解析成功率

**扣分项**:
- 站点数据完全缺失: -2 分
- 观测数据缺失: -1 分
- 预报数据缺失: -1 分
- 关键字段（温度、降水）缺失: -0.5 分/项
- 解析错误: -1.5 分

**计算方法**: `10 + 各项扣分`，最低 0 分，最高 10 分

---

## 权重配置

| 组件 | 权重 | 理由 |
|------|------|------|
| recency | 30% | 数据时效对结算验证至关重要 |
| model_agreement | 30% | 多源一致性是可靠性的核心指标 |
| volatility | 20% | 预测稳定性影响结算预期 |
| data_gap_risk | 20% | 数据质量是基础保障 |

## 评分等级

| 分数区间 | 等级 | 建议 |
|----------|------|------|
| 8-10 | 🟢 高置信度 | 数据可靠，适合参与 |
| 6-7.9 | 🟡 中等置信度 | 数据尚可，注意风险 |
| 4-5.9 | 🟠 低置信度 | 数据质量存疑 |
| 0-3.9 | 🔴 不推荐 | 数据不足，谨慎参与 |

## 输出格式

### JSON 输出

```json
{
  "weather_signal_score": 7.8,
  "weather_signal_components": {
    "recency": {
      "score": 9.9,
      "value_hours": 0.1,
      "note": "数据更新距现在的小时数"
    },
    "model_agreement": {
      "score": 5.0,
      "note": "多站点温度一致性 (stdDev proxy)"
    },
    "volatility": {
      "score": 6.4,
      "note": "预报多样性 (站点间差异 proxy)"
    },
    "data_gap_risk": {
      "score": 10.0,
      "note": "缺测/字段缺失惩罚"
    }
  }
}
```

### Markdown 输出

自动生成 `weather-watchlist-{date}-scored.md`，包含评分表格和汇总统计。

## 局限性

1. **Proxy 依赖**: 当前使用站点间差异代替模型间一致性，后续可接入多模型数据
2. **历史数据缺失**: 无法计算真实的历史波动性，当前使用预报多样性作为 proxy
3. **站点覆盖有限**: 仅覆盖美国主要城市，国际站点数据可能不完整
4. **时间窗口**: 评分基于特定时刻的快照，实时性有限
